# Подключение инструмента к TtRP

Как инструмент из этого репозитория появляется на сайте Time to Roleplay. Инструменты на сайт попадают только отсюда: TtRP собирает их из исходников при сборке сайта и раздаёт со своего хоста инструментов.

## 1. Порядок

1. **Идея.** Для нового инструмента сначала откройте issue: что он делает, кому нужен, какие нужны возможности и примерный размер. Так вы узнаете, возьмём ли мы его, до того как потратите время.
2. **Разработка.** `npm run create-tool -- <id> "Название"`, правила — [best-practices.md](best-practices.md).
3. **Pull request** с инструментом (или новой версией): описание, скриншот или короткое видео, заполненный чек-лист из шаблона PR.
4. **Права.** В PR вы принимаете [CLA](../legal/cla.md) — это условие любого вклада. Для подключения к сайту — ещё и [Условия подключения инструментов](../legal/tool-terms.md).
5. **Ревью.** Команда TtRP проверяет код (безопасность, производительность, интерфейс), может попросить изменения или внести их сама.
6. **Подключение.** После слияния TtRP решает, какие возможности и лимиты выдать инструменту, добавляет его в каталог сайта и выпускает со следующим обновлением сайта. Каталог — внутренняя настройка TtRP, в этом репозитории его нет.

Решение о подключении, его сроках и об отключении инструмента принимает ООО «ТТРП»; слияние PR не обязывает подключать инструмент.

## 2. Чек-лист перед PR

**Сборка и тесты**

- [ ] `npm run check` проходит.
- [ ] Есть тесты логики и состояния; тест сверяет версию схемы с манифестом.

**Манифест**

- [ ] `id` совпадает с именем папки; `title` и `description` — по-русски, понятны игроку.
- [ ] `version` увеличена, если инструмент уже выпускался.
- [ ] `storageSchemaVersion` совпадает с кодом; при смене схемы есть миграция.
- [ ] `requestedCapabilities` — только то, что действительно используется.
- [ ] Размеры окна: инструмент удобен и в минимальном размере.

**Песочница** (`npm run dev`, <http://localhost:5180>)

- [ ] Запуск и рукопожатие без ошибок в журнале и консоли.
- [ ] «Запустить заново» восстанавливает состояние.
- [ ] «Закрыть окно» — инструмент отвечает `closeReady` до таймаута.
- [ ] «Уйти из раздела» — после перезапуска есть всё, что было сохранено.
- [ ] «Отозвать сессию» — инструмент останавливается и больше не сохраняет.
- [ ] Без `LOCAL_STATE` и с маленьким лимитом состояния инструмент работает и понятно об этом сообщает.
- [ ] «Скрыть окно» ставит анимацию и таймеры на паузу.
- [ ] Собранная версия работает так же (`npm run build -- --host-origins http://localhost:5180`, `npm run serve`, `npm run dev -- --host-only`).

**Ограничения**

- [ ] Нет сетевых запросов и ресурсов с чужих адресов, нет `eval`, форм, `window.open`, диалогов браузера.
- [ ] Данные выводятся через `textContent`/`value`, не через `innerHTML`.
- [ ] Размер сборки указан в PR; больше 150 МБ — с обоснованием.
- [ ] Новые зависимости и ресурсы перечислены в PR, их лицензии разрешительные.

## 3. Что проверяет TtRP на ревью

- **Безопасность:** нет попыток выйти за пределы окна, обратиться к сети или к родительскому документу, собрать данные пользователя; нет скрытого и минифицированного стороннего кода.
- **Ресурсы:** размер сборки, нагрузка на процессор и видеокарту, поведение свёрнутого окна, утечки при закрытии.
- **Интерфейс:** русский язык, соответствие стилю TtRP, работа с клавиатуры, понятные ошибки.
- **Права:** принят CLA, у зависимостей и ресурсов подходящие лицензии.

## 4. Новая версия

- Новая версия — отдельный PR с увеличенной `version` и описанием изменений.
- На сайте одновременно работает одна версия инструмента: после обновления сайта окна открываются новой версией, её `state.load` получает сохранения прошлой — поэтому миграция схемы обязательна.

## 5. Отключение

TtRP может выключить инструмент в каталоге в любой момент — например, при уязвимости или жалобах пользователей; код остаётся в репозитории. Автор может попросить отключить свой инструмент — см. [Условия подключения](../legal/tool-terms.md).

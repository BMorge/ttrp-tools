# Архитектура встраивания

Как инструмент живёт внутри TtRP: что видит пользователь, как изолирован код, как устроены связь с оболочкой, состояние и доставка. Справочник сообщений — в [protocol.md](protocol.md).

## 1. Что видит пользователь

- Раздел «Инструменты» (`/tools`) на сайте TtRP: слева список инструментов, справа рабочая область с окнами. Раздел доступен после входа и только на компьютере (ширина от 1024 px, мышь или тачпад).
- Одновременно открыто до трёх окон; окна можно двигать, менять размер, сворачивать и разворачивать. Один инструмент может быть открыт в нескольких окнах, если манифест это разрешает (`window.multipleInstances`).
- Раскладка окон и их состояние сохраняются: уход из раздела и возврат восстанавливают окна. **Закрытие окна крестиком удаляет его состояние.**
- Рабочая область одна на пользователя в браузере: если открыть раздел во второй вкладке, она предложит забрать окна себе, и в первой вкладке они закроются.

## 2. Изоляция

Каждое окно — `iframe` с отдельного origin инструментов: на проде `https://tools.timetoroleplay.ru`, локально `http://localhost:5173`. Сайт TtRP и инструменты — разные origin, поэтому код инструмента не видит DOM, токены, cookie и хранилища сайта.

```html
<iframe sandbox="allow-scripts allow-same-origin" referrerpolicy="no-referrer" src="https://tools.timetoroleplay.ru/dice/0.1.0/index.html">
```

Песочница iframe разрешает только скрипты и собственный origin инструмента. Нет `allow-forms`, `allow-popups`, `allow-modals`, `allow-downloads`, `allow-top-navigation`: формы не отправляются, `window.open`, `alert`/`confirm`/`prompt` и скачивание файлов не работают, уйти со страницы сайта инструмент не может.

Хост инструментов отдаёт заголовки (`scripts/lib.mjs`, `toolResponseHeaders`; продовый nginx повторяет их):

| Заголовок | Значение и смысл |
|---|---|
| `Content-Security-Policy` | `default-src 'self'`; скрипты только свои (`'wasm-unsafe-eval'` — для WebAssembly), без `eval`; `connect-src 'self'` — никаких запросов на чужие адреса; картинки — свои, `data:` и `blob:`; воркеры — свои и `blob:`; `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`; `frame-ancestors` — только доверенные оболочки |
| `Permissions-Policy` | камера, микрофон, геолокация, платежи, USB и полноэкранный режим выключены |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `no-referrer` |

API сайта TtRP не разрешает запросы с origin инструментов (CORS), поэтому инструмент общается с сайтом только через bridge.

## 3. Рукопожатие

Оболочка знает, какой инструмент и какой версии она открыла; инструмент знает, каким оболочкам доверять (список origin зашит в сборку, `__TTRP_HOST_ORIGINS__`).

```text
Оболочка (timetoroleplay.ru)                    Инструмент (tools.timetoroleplay.ru)
  iframe load
  HOST_HELLO {instanceId, windowId, appId,  ──▶  connectToHost(): origin в списке доверенных,
              appVersion, challenge}               источник — родительское окно, appId свой
  (повтор каждые 250 мс, до 15 с)
                                            ◀──  TOOL_READY {challenge, instanceId, appId, appVersion}
  проверки: точный origin инструментов,
  event.source == iframe, challenge,
  instanceId, версия bridge, appId/appVersion
  HOST_CONNECT {grantedCapabilities, locale, ──▶  клиент готов: client.request(...), client.subscribe(...)
                visible} + MessagePort
  дальше — только через MessagePort
```

После `HOST_CONNECT` все запросы и события идут через `MessagePort`. Чьё это состояние (пользователь, инструмент, окно), оболочка берёт из своей привязки, а не из сообщений: инструмент не может прочитать или записать чужое окно.

Если инструмент не ответил за 15 секунд, перезагрузился или ответил не той версией, окно останавливается с ошибкой и предлагает перезапуск.

## 4. Возможности (capabilities)

Инструмент получает только то, что одновременно:

1. запросил в манифесте (`requestedCapabilities`);
2. разрешил ему каталог TtRP — решение команды TtRP при подключении;
3. реализовано в SDK — сейчас только `LOCAL_STATE`.

Остальные имена (`ASSETS`, `FILES_IMPORT`, `FILES_EXPORT`, `ROOM_CONNECT`, `CHARACTER_READ`, `CHARACTER_SAVE`) зарезервированы под будущие возможности. Без выданной возможности соответствующие методы отвечают `CAPABILITY_DENIED`, поэтому инструмент проверяет `client.grantedCapabilities` и умеет работать без неё.

## 5. Состояние окна

- Состояние хранит оболочка, а не инструмент: на сайте — IndexedDB origin TtRP, в песочнице — `localStorage` песочницы. Ключ — пользователь, инструмент и окно; инструмент их не видит.
- Инструмент читает состояние методом `state.load` и пишет `state.save`. Сохраняется снимок `{ state, schemaVersion, updatedAt }`, где `state` — обычные JSON-данные (объекты, массивы, строки, конечные числа, `true`/`false`/`null`, вложенность до 64).
- Размер ограничен каталогом (`maxStateBytes`, у кубиков 256 КБ); больше — `LIMIT_EXCEEDED`.
- `schemaVersion` не может быть больше `storageSchemaVersion` манифеста. При переходе на новую схему прежний снимок оболочка хранит как резервный: если новую версию инструмента откатят, старая получит свои данные обратно.
- Каждое окно хранит своё состояние: два окна кубиков — две независимые истории.

## 6. Жизненный цикл окна

| Что происходит | Что получает инструмент | Что делать |
|---|---|---|
| Окно свернули или развернули | `VISIBILITY_CHANGED {visible}` | остановить и продолжить анимацию, таймеры, звук |
| Пользователь закрыл окно крестиком | `CLOSE_REQUESTED {reason: USER_CLOSE, deadlineMs: 1500}` | завершить работу и ответить `lifecycle.closeReady`; после этого состояние окна удаляется |
| Пользователь ушёл из раздела, или окна забрала другая вкладка | `CLOSE_REQUESTED {reason: NAVIGATION, deadlineMs: 0}` | оболочка не ждёт: останется то, что уже сохранено автосохранением |
| Выход из аккаунта, вход другим пользователем | `SESSION_REVOKED` | сразу прекратить работу и ничего больше не сохранять; порт закрывается |
| Документ инструмента перезагрузился (`location.reload`, переход по ссылке) | — | экземпляр останавливается с ошибкой `RELOADED`; не перезагружайтесь сами |

Пока в окне есть несохранённые изменения (`lifecycle.setDirty`, его отправляет `createAutosave`), оболочка предупреждает пользователя перед уходом со страницы и перед закрытием окна.

Фатальная ошибка инструмента (`lifecycle.reportError` с `fatal: true`) останавливает окно; нефатальные оболочка только записывает в журнал.

## 7. Сборка и доставка

- Каждый инструмент собирается Vite отдельно в `<out>/<id>/<version>/`: `index.html`, хешированные JS/CSS/ресурсы и копия манифеста. Путь включает версию, поэтому выпущенная версия не меняется; новая версия — новый путь.
- HTML отдаётся с `Cache-Control: no-cache`, хешированные ресурсы — `immutable` на год.
- TtRP собирает инструменты из исходников этого репозитория во время сборки сайта; готовые файлы или код с чужих адресов не подключаются.
- Инструмент загружается только при открытии окна. Размер сборки известен заранее: если он больше 150 МБ, оболочка спрашивает подтверждение перед загрузкой.
- Service worker сайта инструменты не кэширует — повторные открытия обслуживает обычный HTTP-кэш браузера.

## 8. Где что лежит

| Модуль | Сторона | Что делает |
|---|---|---|
| `sdk/protocol.ts` | обе | константы, zod-схемы всех сообщений и манифеста, проверка JSON |
| `sdk/client.ts` | инструмент | `connectToHost`, `client.request`, `client.subscribe`, `createAutosave` |
| `sdk/host.ts` | оболочка | `ToolHostSession`: рукопожатие, выдача возможностей, обработка запросов, события окна |
| `sdk/storage.ts` | оболочка | интерфейс хранилища состояния и хранилище в памяти |
| `sdk/snapshots.ts` | оболочка | правила снимков: резервная копия при смене схемы, откат |
| `dev-host/` | оболочка | песочница — та же `ToolHostSession`, что на сайте |
| `scripts/lib.mjs` | сборка | поиск инструментов, доверенные origin, заголовки хоста, сборка Vite |
